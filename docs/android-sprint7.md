## Account and service boundary
Default APK compiles `src/guest`, without Firebase runtime dependencies, initialization or network account requests. Configured builds compile `src/firebase`: `-PVG_FIREBASE_ENABLED=true`, owner-supplied `apps/android/app/google-services.json` for `com.vidgravity.app`, and an already configured free Email/Password provider. Configuration is ignored by git. This work does not provision a project, provider, paid service, billing, deployed rules or credentials.

Auth uses Firebase's SDK-managed session persistence, email/password registration/sign-in/reset, Auth profile display name, logout and password reauthentication before deletion. Account deletion deletes Auth identity/profile only; local projects/media remain. This build never creates Firestore profiles/Storage objects. If an operator later adds cloud data, deletion must first gain a durable authenticated cleanup workflow. No tokens/passwords are stored in app preferences, saved Compose state or logs. Password fields are masked and cleared after actions. Provider exceptions are mapped to generic errors without echoing personal data or confirming account existence. Firebase initialization failure falls back to guest Settings. All current entitlements are free; no payments/ads/subscriptions or payment SDK.

The configured workflow compiles SDK/UI/unit/instrumentation sources with synthetic demo identifiers; it does not validate real provider delivery or session restoration against a live project. Fake-provider UI tests validate sign-in/profile/logout state. The default API29/35 suite validates guest privacy/offline persistence. No Firebase auth emulator or real account backend is configured in this baseline: real sign-in/reset/reauthentication/delete and provider-session failure behavior remain owner-environment verification, not passed integration claims.

## Privacy and Settings
One Settings screen uses Sprint6 disclosures: Account, Privacy & Data, Storage, Export Preferences, Downloads, Notifications, Appearance, Accessibility, Help and About. Removed unused Android-ID licensing display and unconnected activation dialog. Retained download format/Wi-Fi/automatic share preferences and theme behavior. New default resolution affects only newly imported native-video projects; existing encoding settings remain unchanged.

Analytics/Crashlytics are opt-in and disabled in manifest; configured choices call SDK collection APIs, persist, reset analytics/delete unsent crash reports on withdrawal. Guest controls are explicitly unavailable because SDKs are absent. Advertising-ID permission is removed; ad personalization signals default disabled. Crash/analytics delivery and consent propagation are not live-service tested. A previously explicitly sent report cannot be recalled. Account initialization reapplies saved SDK choices. No custom analytics events, account IDs or personal crash keys are added.

Storage overview measures private files, project metadata, disposable disk thumbnail directory and available volume (not public MediaStore usage). Clear cache evicts in-memory thumbnails and only the owned thumbnail directory; it never sweeps cacheDir, active exports, imports, recordings, projects or published media. Project removal requires confirmation and moves to existing recoverable Studio trash. Last-good saves are separately retained; explicit recovery creates a new project and preserves corrupt originals. Nothing is automatically deleted. Recovery copies/old voiceovers/brand assets consume storage until a future reference-aware management workflow exists; uninstall/OS clear-data still removes private projects.

Android settings links expose real app permissions, notification channels and accessibility controls. Foreground worker notifications remain mandatory. Native Studio/captions/templates/local analysis/save/export run without accounts or app network calls. Capture/import still require relevant permissions/readable local sources. Downloads/link inspection and legacy service-rendered tools need internet and send selected URL/media to the configured API on request. Optional Android speech dictation remains provider-dependent. No universal offline speech promise.

## Security audit and repairs
- Metadata reads are bounded before allocation growth (1,024,000 bytes; existing decoded project limit 256,000 characters retained). Project IDs are validated, filename/content IDs must match, corrupt/unknown formats remain intact. AtomicFile writes, cross-instance lock and stale-save rejection remain. Last-good recovery is app-private and explicit, not silently substituted.
- Content URI validation rejects remote/file schemes, missing authority, credentials, port, fragment and oversized strings; actual resolver permissions/MIME and video decoding still gate imports. No broad storage permission added; SAF read grants/MediaStore remain. Cloud-only document providers can still require network; choose locally available media for offline work.
- Existing cache FileProvider URI prefix retained to avoid breaking saved local media. SafeMediaProvider restricts cached access to contained media filenames and read-only opens. JSON/preferences/log/cache metadata and path traversal cannot be read through it. Other configured roots remain narrow Pictures/Movies/Music/media. Read grants remain explicit; provider non-exported. Cached media are temporary and can be removed by OS, so durable document sources remain preferred.
- Manifest: backup disabled, cleartext disabled, camera/microphone optional hardware, only launcher and text ShareReceiver exported. Camera/GhostPlayer/receiver remain private. Existing normalized text-share URL checks reject credentials/private hosts; no WebView or new external media deep link added. GhostPlayer remains unused private legacy scaffold.
- Existing HTTPS API pin, cleartext policy, bounded normalized URL validation and scoped storage are retained. Backend SSRF defense and cloud service authorization are separate server responsibilities. No production network, Firebase or Cloudflare change.
- No credentials/tokens/PII logging added; existing VGStartup/VGStudio logs contain lifecycle/timeline counts. No cryptographic project-encryption claim: Android sandbox/backup exclusion protect private files; rooted devices and compromised OS are outside that boundary.
- Debug APK deliberately debug-signed. No release signing key or release certification is supplied. Dependency inventory is produced for configured builds; existing Media3/Compose/CameraX versions retained. Full advisory scanning is not established, so no vulnerability-free claim.

## Proposed #64 rules review (not copied/deployed)
See `android-sprint7-rules-audit.json`. Firestore owners only at users/{uid}; identical create/update field whitelist, lengths/types and server timestamp. Storage owner-only fixed private-image path, size/type/id checks for create/update, no listing/unknown paths. UID comes from request.auth, no client privilege fields. Proposed Storage MIME metadata is not image-content verification: a malicious owner can store arbitrary bytes labeled image; require trusted image decoding/re-encoding before any future rendering/serving integration. Authenticated ownership is not email verification; decide if verified identity is necessary before future sharing. Rules emulator tests in #64 have not been imported or rerun here, and proposed rules are not evidence of deployed rules. This sprint makes no Firestore/Storage calls, avoiding accidental dependence on unknown production rules.
